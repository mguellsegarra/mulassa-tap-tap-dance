## Desktop entry stall investigation (2026-11-05)

Owner report: Chrome on mbp-m1 pauses for 1–2 seconds immediately after the first splash tap, then recovers. This symptom has not been reproduced at that duration on mac-studio. No runtime JavaScript errors appeared in the sampled entries.

Profile on mac-studio, Chrome 157.0.8103.39, headless real Metal (Apple M5 Max), 1280×800, DPR 1, fresh isolated contexts: first active Bou entry had a 154 ms task / 150 ms frame. About 63 ms of CPU profiler samples were in getParameter → getMaxAnisotropy → bou-bills.js image callback. This is a synchronous driver query issued when the Bou banknote texture arrives. Three.js caches the result, explaining why a repeated entry does not pay it.

The capability query now runs in precompile under the loader, before scene compilation/first frame. No image quality, model, music or choreography changes. The first subsequent pass and fresh-process rechecks had no task over 50 ms and a longest frame of 33.4 ms. HOWEVER a fresh-process baseline with the query removed also then had no task over 50 ms / 33.4 ms: the driver/system caches were warm. These results prove the deferred synchronous query was moved, not that the owner's cold 1–2 s freeze is fixed. Original raw first-pass files were overwritten during rerun; its numbers and stack were recorded in tool output, while named baseline/candidate JSON profiles remain in output/release-1.4.0/entry/.
