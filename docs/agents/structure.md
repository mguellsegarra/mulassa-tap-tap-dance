# Structure of the codebase

`src/main.js` is only the composition root (imports in start order, the keyboard/pointer wiring's glue, the frame loop);
every system lives in its own module, and `tests/build/modules.mjs` keeps it that way (no import cycles, main.js ≤ 400 lines,
every other module ≤ 300). Modules with page-level state (`let`s other modules read) export a `setX()` for the ones they
let others change; the sheets (board, share, profile, Perfil `account`, seasons, season end, card, feedback, sync) are built in `ui/sheets-setup.js` and read
by everyone below it as `sheets.board`… (`ui/sheets.js`), so no import cycle is needed.

- `index.html` — the DOM: touch pad (GUA | PA), ⚙ `#settings` → "Configuració" sheet, "Com es juga" pill + sheet, "Ajusta la
  sincronia" sheet, pause/confirm sheet, SALTA, the device tips (`#gpu-hint-menu`; free play's `#free-hint-menu`). Its CSS is in `src/styles/*.css` (`base.css`, the boards' `board.css`,
  `share.css`, `feedback.css`, the selector's `select.css`, `select-cards.css`, `select-sizes.css`, `select-pending.css`, `select-chrome.css`, then `profile.css`, linked in order) except the fonts and the `#loader` rules, which stay inline: they paint before any file.
- `src/main.js` — imports the systems in start order, the keyboard/pointer glue that needs several of them, `frame()` (the time step, then `game/tick.js`, the animations, `ui/frame-camera.js`, the render and the HUD),
  `window.__dbg` for tests.
- `src/core/` — `flags.js` (the ONE reader of the URL's debug flags: `Q` is empty on any non-dev host, so debug parameters are ignored on mulassa.cat/pages.dev; real features `?repte` and `?lang` read their own search in share.js and i18n/locale.js), `env.js` (flag constants, beat grid, judge window in use, sync offset), `timing.js` (frame pacer, lane clock), `anim.js` (clock-driven easing: `pulse`, `hold`), `math.js` (pure angles, clamps and easing curves, no imports).
- `src/game/` — the rules, no drawing, except `flow.js`, `judge.js` and `tick.js` (one frame of the rules: finale triggers, meters, autoplay), which orchestrate `hud/`, `scene/` and `ui/`: `state.js` (`G` and who owns each field, `chip`, `clock`, the song clock, held keys),
  `flow.js` (splash → select → run/practice → finish → final), `judge.js` (hits, GUAPA pairs, holds, balloons, collapse, autoplay/advance),
  and the pure logic: `chart.js` (`makeDanceChart`, `DIFFS`, `BALLOONS`), `progress.js` (quality %, stars, `WINDOWS`), `energy.js`
  ("l'ànim de la plaça"), `practice.js` (first-game `STEPS`), `calibration.js`, `dance.js` (the old beat choreography and the dance factories), `mula-*.js` (the Mulassa's reference-led dance, below),
  `showreel.js` (the selector's showreel: the selected figure's whole song dance on the menu loop's beat, a song beat per menu beat, and its shot list, cuts on the loop's bars), `bubble-rules.js` (when the crowd may talk), `figure-catalog.json` (names, towns, entities and primary sources), `figures.js` (playable/Aviat registry, portraits, per-figure level memory and record keys), `records.js` (the device's record per level and version, the previous dance's read-only), `stats.js` (the device's statistics, per owner: counters per `figure/version/level` bucket, practice, days played; pure). Catalog thumbnails use native pixel cells and palettes in `figure-portraits.js`, rendered through the original `pixelSvg` component.
- `src/figures/` — one folder per playable figure (`mulassa/`, `drac/`, `bou/`) and `common/` (the colla and the fire every figure builds on): its model, rig, dance, feet, colla, festa and portrait modules, moved together so a figure is one unit; each, the Mulassa too, builds and owns its model and colla (`<key>-objects.js`, a line in `figures/objects.js`: `COLLAS`, `figureRoot`, `hideFigures`, which the low layers go round; `scene/stage.js` keeps only the plaça) and exports its stage hooks (`<key>-scene.js`: shown, colla, motion, share photo, end shot; its motion in `<key>-play.js`) and what it does to the crowd (`<key>-crowd.js`, a line in `scene/crowd-effects.js`: rooted, posed, steered, its festa) with one line in `scene/figure-scenes.js` (tests/figures/common/scenes.mjs keeps them in step). `index.js` is the traits table (`FIGURE_TRAITS`: short name, drumroll element, article, share file and caption, challenge, play camera, free-play clearance and keys, the PHOTO body it drives, whether M is its own body, splash host/partner, landing shake): the shared systems read a trait instead of testing an id; a new figure adds its folder and one row (tests/figures/common/traits.mjs keeps them in step).
- **Figure hook registries** — a new figure adds one row or line to each and nothing else in `scene/`: `figures/index.js` `FIGURE_TRAITS` (data, `tests/figures/common/traits.mjs`), `figures/objects.js` (its model and colla; `tests/build/modules.mjs` keeps the low layers going through it), `scene/figure-scenes.js` (stage hooks) and `scene/crowd-effects.js` (what it does to the crowd), both kept in step by `tests/figures/common/scenes.mjs`. A figure's folder owns `<key>-objects.js`, `<key>-scene.js`, `<key>-play.js`, `<key>-crowd.js` and `<key>-portrait.js` (the Mulassa's prefix is `mula-`), and its song is `src/song-<key>.json`. No figure-id check outside `src/figures/`: add a trait or a hook.
- `src/scene/` — the 3D world: `stage.js` (renderer, scene, lights, plaza, mulassa, the play camera's direction), `quality.js`
  (a render-quality level applied), `crowd-build.js` (who stands where), `crowd.js` (`animCrowd` = `updateMood` →
  `steer` → `separate` → `pose` → `poseScenery`; the mood is the `mood` object in `crowd-mood.js`, the neighbour grid `crowd-grid.js`, the pose `crowd-pose.js`), `stage-motion.js` (the frame of the figure on show: resets, free play's start and end, the splash pair; every figure, the Mulassa too, moves through its hooks in `figure-scenes.js`; the shared springs and `M` are `figure-springs.js`, free play's jumps and shake `manual-jump.js`),
  `cameras.js` (the menu camera), `play-camera.js` (`framePlayCamera`), `confetti.js`, `fx.js` (finale lights, fireworks), `share-capture.js` (`renderHero`), `balloon3d.js` (the GLOBUS
  balloon in 3D), `models.js` → `models/*.js` (voxel models by subject), `framing.js`, `orbit.js` (pure camera helpers), `crowd-fx.js` (the ripple), `representation.js` (+ `representation/`: the public's, musicians' and attendants' looks drawn over the crowd's rigs; approved weights in `src/scene/representation/population.js`; `?representation=off` = the original cast).
- `src/hud/` — everything drawn on the 2D canvas: `canvas.js` (size, K, safe areas, resize), `sprites.js` (palette + text sprite cache),
  `primitives.js`, `layout.js`, `lane.js`, `top.js`, `praise.js`, `bubbles.js`, `banner.js`, `title.js`, `results.js`, `warm.js`, `balloon.js`,
  `draw.js` (`drawHud`), plus `stars.js`, `logo-motion.js`, `share-card.js`.
- `src/ui/` — DOM: `handles.js`, `sheets-setup.js`, `input.js`, `controls.js`, `pause.js`, `pause-actions.js`, `pad.js`, `focus.js`,
  `src/ui/backdrop.js`, `fullscreen.js`; the sheets `board-ui.js` (+ `publish-ui.js`: the publish sheet), `profile-ui.js`, `share-ui.js`, `feedback-ui.js`, `sync-sheet.js`,
  `account-ui.js` (Perfil: profile block, statistics, podiums, previous record, the statistics notice), `stats-view.js` (the statistics' tiles, private or public), `seasons-ui.js` (season calendar and words, the Saló de la fama; the end-of-season sheet is `season-end-ui.js`; the per-owner get_seasons cache), `board-list.js` (the Classificació sheet's list; `board-reads.js`: the selector's reads of the boards), `figure-picker.js` (the figure dropdown shared by Classificació and the Saló de la fama), `player-card.js` (a player's public card), `greeting.js` (what the idle selector tells a profile), `device-hint.js` (the device tips: hardware acceleration, iPhone home screen),
  `loader.js`, `select-ui.js` (main selector, town pills, records and inline pending information; its keys and layout measure are `select-keys.js`, `select-layout.js`), `select-flip.js` (a pending figure's re-layout slides by a transform instead of jumping: no layout shift), `level-stats.js` (step 2's level row), `free-music.js` (photo mode's radio); helpers `sheet-kit.js` (status line, busy button), `sheet-fade.js`.
- `src/services/` — talking to the outside: `leaderboard.js` (+ `leaderboard-rules.js`, `leaderboard-result.js`, `leaderboard-errors.js`, `leaderboard-identity.js`: the stored name, `savedName`/`refreshIdentity`, `supabase-client.js`, `alias-rules.js`),
  `stats-sync.js` (uploads the device's statistics to the open profile), `feedback.js` (client of the `workers/feedback` Cloudflare Worker, `VITE_FEEDBACK_URL`; the Worker checks Turnstile and e-mails each
  message to the `FEEDBACK_TO` secret, nothing stored, never put a personal address in the repo), `captcha.js` (Turnstile), `share.js`,
  `errors.js` + `sentry-load.js`.
- `src/platform/` — `audio.js` (`Chip`: song + menu loop + SFX, with `audio-clock.js`, `audio-load.js`, `audio-voices.js`, `audio-radio.js`, `applause.js`; `clicker.js`: the calibration's `Clicker`), `render-quality.js` (adaptive DPR/quality, frame pacer),
  `storage.js` (the one localStorage adapter), `polyfills.js`.
- `src/i18n/` — the UI's languages: `locale.js` (the effective language, read once at startup), `load-locale.js`/`preload.js`, `messages.js`/`catalog.js`, `apply-dom.js`, `format.js`, `fonts.js`, `boot-jokes.js`, `pseudo.js` (`?lang=pseudo`), `locales/<code>/`; the saved choice is written only by `ui/lang-ui.js`.
- `src/music-form/` — compiles a figure's music form into the song JSON (`compile.js`, `songs.js`; contract in `CONTRACT.md`). Photo mode's camera, motion, collisions and obstacles are `scene/photo-*.js` (rig in `game/photo-control.js`); the home-screen app's update check is `services/update.js` + `update-rules.js`.
- `tools/` — by kind: `music/` (the generators, the form compiler, the music editor's dev backend), `qa/` (GPU captures, the UI inventory and videos, review and audit scripts), `deploy/` (the public pages, the Pages allowlist, Cloudflare), `data/` (database backups, leaderboard cleanup, score ceilings), `bestiari/` (reference-video research), `dev/` (below).
- `tools/dev/` — the dev-only HTML pages and their code (`editor.html` + `tools/dev/music-editor/`, `drac-compare.html` + `drac-compare/`, `mulassa-compare.html` + `bestiari-compare/`, `bou-dance.html`, `bou-review.html`, `colla-preview.html`, `mulassa-contrast.html`, `mulassa.html`: the Mulassa model and its song dance, ?from=N, `notes.html`: the Bou's audio with the score note sounding, per voice, to point at one, `notes-propostes.html` + `notes-propostes/`: the Mulassa's three charts against three proposals, playable, with a per-level note editor that exports JSON, `bou-propostes.html`: the Bou's festa ideas on its song, disco floor, banknotes, carretilles, day/night, `reel-review.html`: the showreel and «Mira el ball» live at several viewports side by side, with its shot plan (refs M1…, D1…) over the dance parts), served by `npm run dev` at `/tools/dev/…`, never built (`vite build` reads `index.html` only).
- `src/dev/` — only the dev modes the game itself reaches, gated to dev hosts: `mock-leaderboard.js` (the in-memory leaderboard behind `?mock`/`?final`/`?demo`: the real service over a fake client, `mock-client.js`, and a seeded world, `demo-data.js`, both loaded on its first call), `account-review.js` (`?final&review=`), `cam-edit.js` (`?cam`) and `sizes-edit.js` (`?sizes`), loaded with `import()` only when asked for, `perf.js` (`?perf`), `debug.js`, `final-test.js` (`?final`). Nothing in it may be imported statically unless it is tiny: the published game downloads every static import.
- `src/song-mulassa.json` — **generated** (never hand-edit): bpm, beats, sections, finale, end, notes
  `[t, don|ka, level, big, holdEnd]`, hashed audio URLs.
- `src/song-bou.json` — **generated** by `node tools/music/build_bou_chart.mjs` from the approved package in `music/bou-tradicional/` (the MP3 is copied byte for byte, never re-encoded). The Bou's model, dance, colla, festa and final are described in `docs/figures/bou.md`. Its score version `bou-v1` has no server board yet (`hasBoard`, figures.js): never published, its statistics stay on the device.
- `tools/music/build_drac.py` — the Drac's generator (form `music/drac/drac-form.json`, Festiva arrangement, tempo map fitted to the
  reference video, `song-drac.json` with its `ref` time map); `docs/figures/drac-music.md`. Mulassa audio must stay bit-identical.
- `tools/music/build_taiko.py` — the **single** generator of all music and the chart, from `music/mulassa/score.json`
  (the melody). Writes `public/music/mulassa-taiko.{wav,mp3,mid}`, `mulassa-taiko-ambient.mp3`
  (the `.mid` scores are versioned, not deployed; the `.wav` stays ignored), `music/mulassa/taiko-arrangement.json` and `src/song-mulassa.json`. Musical/game rules: `music/README.md` (Catalan).
- `check.mjs` (chart invariants) + `tests/` (node, no browser), by area: `figures/<mulassa|drac|bou|common>/`, `game/`, `render/`, `ui/`, `services/`, `db/`, `build/`; `tests/run.mjs` finds every test by itself (a file no other test imports; check.mjs and `tests/build/modules.mjs` first, Python tests listed; run in parallel, real-browser and self-timing tests alone at the end). `build/modules.mjs` the shape of `src/`; `tests/render/render-quality.mjs` runs the
  game's systems together in a mocked DOM (`game-context.mjs`: `nodes.get(id)`, `run(code)`) for HUD/sheet/game contracts, one file per area run in its order on one shared game — `tests/render/load-main.mjs`
  concatenates `main.js` and every module it reaches (except the ones the context provides) into ONE script, so the snippets can read
  and assign the systems' top-level names; a module you add is picked up by itself, but keep its imports on one line and its
  top-level names unique (the harness fails naming both files when two inlined modules declare the same one); `tests/ui/page.mjs` reads `index.html` with the linked CSS put back inline; `tests/game/onboarding.mjs` practice + sync;
  `tests/game/energy.mjs` ànim tuning; `tests/game/bubbles.mjs` crowd bubbles; `tests/build/audio.mjs` loading/wake.
