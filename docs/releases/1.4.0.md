# 1.4.0: Bou Tradicional de Valls (checklist)

Release branch `release/1.4.0`; the Bou is already playable (`UNRELEASED_IDS` in `src/figures/index.js` is empty), so the
selector, play, free play and the production bundle include it. Scheduled for 2026-11-19 (Pop 1.3.0 went out 2026-11-12,
Memory 1.5.0 follows 2026-12-03). The Memory stays out of this release. How a deploy goes: `docs/ops/deploys.md`.

## Before the tag

- [ ] `package.json` and `package-lock.json` bumped to `1.4.0` together (they are on 1.3.6); `three` stays pinned to `0.180.0`.
- [ ] The owner's visual and listening OK on the Bou's music (`music/bou-tradicional/playback.json`, revision 21, v14-mobile:
      `agentListeningVerified`, `physicalPhoneVerified` and `userListeningAccepted` are all still `false`) and on a physical phone.
- [ ] `npm run check`, `npm run check:gpu` and, for the release, `npm run check:full` green; production build verified
      (`tools/deploy/prepare-pages.mjs` also refuses a QA build, a `-qa` stamp in `version.json`).
- [ ] Blocking cost of the Bou's screens and its final measured on the reference Android (`docs/agents/device-profiling.md`).
- [ ] Audio of the other figures bit-identical: `shasum public/music/*` against the 1.3.x build.
- [ ] Release compatibility reviewed (`.agents/skills/mulassacat-release-compatibility/SKILL.md`).

## What stays as it is

- The Bou board is enabled by `supabase/migrations/202611150001_bou_board.sql` before the client.
  Recomputed chart ceilings remain 205000 / 248000 / 323000; `bou-v1` is unchanged.
  Bou statistics use the normal elapsed-time budget. Details and recovery: `docs/figures/bou.md`, "Online board rollout".
- Score version, existing record keys and the Mulassa's and Drac's audio are untouched.
- Each protected operation (merge, tag, deploy) is confirmed separately in chat; nothing here implies it.

## Known risks, accepted by the owner

- The Bou's banknote close-up at the song's end grows the canvas (`hud/canvas.js` `setCloseUp`): one frame of
  about 84 ms on the S10 while the GPU reallocates the framebuffer (2026-11-15). A presentation-buffer fix brought it
  to 50 ms but cost about 114 MiB of GPU memory on every song and more long frames on the Mulassa and the Drac, so it
  was left out of 1.4.0; its patch and numbers are kept outside the repo for a later design without that memory.
