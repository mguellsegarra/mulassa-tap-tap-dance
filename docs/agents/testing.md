# Testing in a browser

- **Always load the game with `?mute`** in any browser, headless or simulator. Close tabs when done.
- Headless Playwright (Chromium, `--use-angle=swiftshader`) and the iOS Simulator are fine for screenshots.
- Frame/glitch checks and videos: `npm run capture -- --url='http://localhost:5178/?mute&autoplay&from=40' --seconds=20 --vp=393x852 --dpr=2 --touch` (`tools/qa/capture.mjs`). Real GPU (Chrome + Metal), not SwiftShader, whose CPU rendering saturates the machine and fakes hitches; one capture at a time (lock `/tmp/mulassa-capture.lock`, shared with `ui-video.mjs`/`ui-inventory.mjs`, `--soft` there = SwiftShader; the inventory's S24 «gpu» scene picks it by itself). It writes `frames.csv` (rAF ms), `summary.json` (fps, p99, spikes), `video.mp4` and `spike-N.jpg` contact sheets: read the numbers first, the video second. The clock starts once `#loader` is gone, so the dev server's load is not counted.
- Check mobile first (375×667 and iPhone 16, 393×852) and desktop (e.g. 1280×800). Orientation (`src/ui/fullscreen.js`): phones run the menus and the game in portrait and free play in landscape (free play in portrait shows «Gira el mòbil en horitzontal»); tablets run everything in landscape. So QA phone menus, sheets, the selector and play in portrait, and phone free play in landscape (e.g. 852×393, 932×430); the other orientation only shows the rotate cover.
- URL params (dev hosts only; `Q` in `src/core/flags.js` is empty elsewhere, so each is ignored on public hosts, except `?repte` and `?lang`, real features that read their own search):
  - `?lowpower=1`: forces the battery-saving warning when starting from the difficulty picker (`ui/lowpower-hint.js`).
  - `?mute` silent; `?autoplay` plays itself (`&jitter=<ms>` presses every note that many ms early or late, deterministic: ~70 ms is BÉ on NORMAL, 300 misses); `?from=N` start at N s; `?still` the Mulassa doesn't dance on the selector; `?offset=ms` sync offset.
  - `?view=side|front|back|top` fixed camera, no HUD; `?camdrac=segueix` the play camera follows the Drac's heading (the old behaviour).
  - `?figura=<key>` the selector opens on that figure (`mulassa`, `drac`, `bou`); `?repte=<pct>-<diff>[-<key>]` a friend's challenge link, also on public hosts.
  - `?festiu=0` the Mulassa's dance without the extra festive sway; `?nobou` the Bou's colla and plaça without the Bou; `?lletres` the helpers' W/N/S/E letters; `?clicks` a tick on every note (sync by ear); `?rawclock` the old stepped audio clock (A/B); `?representation=off` the original crowd cast.
  - `?sizes` the selector figures' heights editor (`src/dev/sizes-edit.js`); `?escala=0.85` forces the selector's zoom (`src/dev/escala.js`); `?vp` a corner label with viewport, dpr, selector zoom and pointer type (`src/dev/vp-label.js`), for reading a device off a photo; `?demo` the selector with a made-up record and position (brings the mock board); `?mock` the in-memory leaderboard; `?final[=<pct>-<diff>-<record|clear|collapse>]` the results/final flow over the mock, `&review=<state>` one of the account flows (states: `REVIEWS` in `src/dev/final-test.js`: `share-drac`, `publish`, `published`, `share`, `email`, `code`, `verified`, `choose-name`, `switch`, `profile-new|reserved|guest|verified-unnamed|verified`, `board`, `board-tip`, `board-guest`, `board-empty`, `board-drac`, `board-drac-empty`, `seasons`, `seasons-later`, `seasons-many`, `seasons-drac`, `season-end`, `season-end-plain`, `card`, `card-guest`, `card-long`, `card-empty`, `taken`, `recover`, `retry`).
- `?cam` (with `?autoplay&from=N`, or a practice): the camera editor over the game (`src/dev/cam-edit.js`). Drag orbits, wheel/pinch = distance, shift- or right-drag (two fingers) = where she stands on the screen, shift+wheel or the buttons = fov; an overlay shows az/el/dist/fov/her screen y next to the automatic camera's, and «copia» copies one JSON line (viewport, K, stage, values, auto) to fit the per-device camera from. The auto camera keeps running underneath («auto» goes back to it).
- Local previews without `VITE_SUPABASE_URL` + `VITE_SUPABASE_PUBLISHABLE_KEY` (`.env.example`) automatically use the existing in-memory leaderboard and show "MODE PROVA"; `?mock` explicitly selects it on dev hosts. Public hosts never use this fallback. It does not skip the splash or fabricate a completed run. Its demo world comes from the URL (`demoOptions`, header of `src/dev/final-test.js`; data in `demo-data.js`, answers in `mock-leaderboard.js`): `&account=new|reserved|guest|verified-unnamed|verified` (who is signed in; the guest is `Prova123#4821`), `&seasons=launch|later` («Estrena 2026» + open Tardor; or Tardor closed with two Mulassa boards and open Hivern 2027, which shows the end-of-season sheet), `&board=empty|me` and `&drac=empty` (empty open seasons; a 119-player ladder with the profile at #48), `&card=Nom[#1234]` (opens that player's card at the first idle selector), `&taken`, `&fail`; `?final&review=<state>` reaches the profile, e-mail and ranking flows by pressing the real sheets' buttons (`&review` alone lists them). The mock service emits `onAccount` events (it wraps `createLeaderboardService`); only the SDK's `onAuthStateChange` is absent in its client.
- `?stars=0-3`: opens straight on the results card with a fake run of that many stars (never a record, never stored); the star animation replays on each load.
- `?perf`: every 3 s logs `[perf]` averages (fps, the display rate `hz` and `half` (pacer ÷2), `late` frames (missed
  their turn: a visible lane hitch), rAF frame ms + worst, JS ms split into `3d` render and `hud` draw,
  draw calls, triangles, WebGL/HUD Mpx, quality) to the console, `window.__perf` and a line at the top of the screen
  (tablets have no console). `?perf=sync` waits for the GPU after the 3D (real 3D cost); `?perf=nohud` / `?perf=no3d`
  skip one part to A/B frame times; `&hide=crowd,backdrop,mid,plaza` (`people` = the first three) hides scene parts on a
  device to find which costs its frames. The line also shows the session's people level and the GPU's name (render-quality.js
  tables). On a slow device, record a DevTools Performance trace: the main thread's style recalc and Layerize per frame
  are DOM work (a style written every frame cost ~10 ms a frame on a 2016 MacBook). Tablet benchmark: Playwright 1366×1024 @ DPR 2, `isMobile`, CDP
  `Emulation.setCPUThrottlingRate` 4, `?mute&perf&autoplay&from=40`, then `__dbg.choose(1)`.
  `?perf` also logs the load stages: `[load] module|shaders|first frame|song decoded <ms since navigation>`.
- The first game ever is the practice; SALTA or `__dbg.startPractice/endPractice` to control it.
- Judge and clock logic is tested without the scene (pure modules); render tests cover drawing only. `node tests/run.mjs game/judge game/chart-playable game/calm-trauma` runs the judge core (window edges, ties, GUAPA partner, holds, balloons), the jittered-autoplay grade mix over the three songs, chart gaps/balloon reachability and the reduced-motion shake.
- Reduced motion: test it with Playwright `reducedMotion: 'reduce'`.
- Leak checks: repeat the action (a run, a sheet, a quality step) and compare `renderer.info.memory` before and after.
